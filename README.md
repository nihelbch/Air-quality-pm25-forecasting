## Data provenance and restrictions

- Other downloaded originals `pm25.csv` and `gee_features_daily.csv` also stay unchanged in `data/raw/` if you have them. They are not required to run this Part 1 script.
- Raw files are excluded from Git by `.gitignore`, but included with this hand-off ZIP for convenience (only `combined_gee_pm25.csv`). You may remove raw CSVs from your public archive if their redistribution is not authorized.

## Install and run in PyCharm

1. Open the ZIP's `PM25_Project_Refactored` folder as a PyCharm project, or copy `src`, `scripts`, `notebooks`, `tests`, `README.md`, etc. into your existing project. **Back up** any files that already exist before replacing.
2. Use Python 3.11+ and create/select your `.venv` interpreter.
3. From PyCharm's **Terminal**, with the current directory at the project root:

```bash
python -m pip install -r requirements.txt
python -m scripts.run_eda
python -m pytest -q
```

4. Open `notebooks/01_eda.ipynb` and `notebooks/02_timeseries.ipynb` using the same `.venv` kernel. Both notebooks load the original dataset with a robust path resolver and reuse `src` code. They do not independently reimplement EDA calculations.

## What's produced by `run_eda`

- `data/processed/pm25_cleaned.csv`: PM2.5 target validation (`0 < pm25 < 500`), other columns kept unchanged except `datetime_utc` removed.
- `data/processed/pm25_forecast_dev.csv`: labelled one-day-ahead development examples.
- `data/processed/pm25_forecast_future_test.csv`: untouched future-period evaluation examples; do **not** train/tune on them.
- `results/Exploratory_Data.csv`: 45-column professor-schema EDA summary.
- `results/Exploratory_temporal.csv`: 35-column professor-schema station diagnostics.
- `results/data_audit.json`: source and cleaning statistics and remaining limitations.
- `results/lead_lag_diagnostic.csv`: descriptive Spearman correlations, **negative lags only for EDA**.
- `figures/eda/` and `figures/timeseries/`: saved PNG plots.
- `folds/folds_temporal.json`, `folds/folds_spatial.json`, `folds/folds_standard.json`: 5 folds per scheme, using indices from the development CSV in its exact saved order.

## Scientific decisions

- This implementation **chooses 1-day-ahead forecasting**, issued at the end of day `t`, predicting PM2.5 at `t+1` using data from day `t` or earlier. Operational availability of those observations must be confirmed for real deployment. It is *not* same-day nowcasting.
- The input features do **not** include station ID or coordinates, and all lags are applied on per-station full daily calendars. Seven-day rolling averages require seven observed days. No backward fill, future-target-based imputation, or cross-station time shift is performed.
- Station eligibility uses only development dates (`target_date < 2025-01-01`), avoiding future-period count peeking. The fixed future holdout starts with **target dates** on 2025-01-01. Only observed origin and target day pairs are used. This may bias the sample toward better-monitored dates/stations; disclose that limitation.
- **Do not prefit** the numeric preprocessor on all development data before CV. Use `src.preprocessing.build_numeric_preprocessor()` *inside each model training pipeline* for each fold. This project does not train models or score the holdout.
- Temporal CV uses TimeSeriesSplit(5) on a *calendar-day timeline*, with one excluded day between training/validation target dates. Spatial CV groups by station ID; review overlapping sites for potential hidden spatial dependence. Random KFold is **diagnostic only**.
- ACF lag 24 is **24 days**, not diurnal, for daily data. No diurnal amplitude is reported. Tests on contiguous observed runs are limited by sparse station sampling. The temporal `n_cycles_observed` counts years with >=10 observations in all 12 months; it does not prove genuine annual cycles.
- LOF outlier counts use a deterministic <=15,000 complete-row subset for resource control; IF uses all complete rows. Neither flags are grounds for automatic deletion of plausible pollution extremes.
- The default `MODEL_GROUP='G18'` was copied from the notebook and must be verified against your professor-assigned group (G18 = 1D-CNN in the project specification).
